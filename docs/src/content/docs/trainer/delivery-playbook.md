## Run-of-day agenda

The day runs from 08:30 to 17:00 and totals exactly 510 minutes.

| Time | Duration | Segment | Evidence handoff |
| --- | --- | --- | --- |
| 08:30-09:00 | 30 min | Welcome and Train-the-Trainer orientation | Pairing plan and evidence location. |
| 09:00-09:30 | 30 min | M0 - Setup | Environment readiness notes. |
| 09:30-10:15 | 45 min | M1 - Foundations and certification readiness | B.1.1 cert mapping and readiness plan. |
| 10:15-11:15 | 60 min | M2 - Workload assessment | B.2.1 dependency map and backlog. |
| 11:15-12:45 | 90 min | M3 - Solution design and WAR | B.3.1 design and diagram; B.3.2 WAR export and backlog. |
| 12:45-13:30 | 45 min | Lunch | Trainer evidence check. |
| 13:30-15:00 | 90 min | M4 - Delivery | B.4.1 delivery artifacts and diagrams. |
| 15:00-16:00 | 60 min | M5 - Service validation and testing | B.5.1 validation evidence and customer sign-off. |
| 16:00-16:45 | 45 min | M6 - Operate | B.5.2 operating documentation and monitoring evidence. |
| 16:45-17:00 | 15 min | Wrap and Train-the-Trainer debrief | Final evidence checklist and trainer actions. |
| **Total** | **510 min** | **08:30-17:00** | **All Module B evidence collected.** |

## Setup emphasis

Use a room layout that supports short demos, paired work and roaming facilitation. Pre-stage Azure access, tooling, Copilot agent availability, MCP server connectivity and a shared evidence location before learners arrive.

## Pacing model

Use one shared backbone with two speeds: a guided path for newer learners and stretch goals for experienced learners. Demo risky setup, identity and reconciliation steps; let learners drive assessment, design, validation and operations evidence.

## Module defaults

| Module | Default facilitation mode |
| --- | --- |
| M0 | Demo then drive. |
| M1 | Guided discussion. |
| M2 | Learner drive with checkpoints. |
| M3 | Demo design framing, then learner artifact work. |
| M4 | Demo risky deployment steps, then learner evidence work. |
| M5 | Learner drive with trainer acting as customer. |
| M6 | Learner drive from operations templates. |

## Handoff rule

At every module boundary, ask teams to name the control, show where evidence is stored, check one sample artifact against the rubric and capture unresolved risks in the remediation log.
